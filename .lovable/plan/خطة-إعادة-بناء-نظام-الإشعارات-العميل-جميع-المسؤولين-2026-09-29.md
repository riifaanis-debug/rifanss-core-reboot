# خطة إعادة بناء نظام الإشعارات (العميل + جميع المسؤولين)

النطاق: الإشعارات داخل الموقع فقط. لا تغيير على الدخول أو OTP أو Resend أو نصوص العقود والسندات والفواتير أو الأتعاب أو التصميم العام. البريد الإداري الحالي يبقى كما هو.

## 1. قاعدة البيانات (أقل تعديل آمن)

**جدول `notifications` الحالي (يبقى لإشعارات العميل)** — إضافة أعمدة اختيارية فقط، بدون حذف أو تغيير نوع:
- `target_type` (request / contract / promissory_note / invoice / open_request / payment_request)
- `target_id` (معرّف العنصر نفسه)
- `event` (اسم الحدث مثل request_submitted, contract_issued...)
- `archived_at` (أرشفة العميل لإشعاره)
- قيمة افتراضية للمعرّف من القاعدة (`gen_random_uuid()::text`) بدل NOT-{وقت المتصفح}.
- فهرس على (user_id, created_at).

**جدول جديد `admin_notifications`** — إشعار إداري واحد مشترك لجميع المسؤولين:
- id (uuid)، event، title، message، submission_id، target_type، target_id (يشمل `customer`)، customer_id (→ app_users)، created_at.

**جدول جديد `admin_notification_states`** — حالة كل مسؤول على حدة:
- notification_id (→ admin_notifications، حذف متتالٍ)، admin_user_id (حساب المسؤول)، read_at، archived_at، مفتاح فريد (notification_id, admin_user_id) وفهارس.
- غياب السجل = غير مقروء وغير مؤرشف لذلك المسؤول. قراءة (A) لا تمس (B).

**الإنشاء الآمن للإشعار الإداري:** دالة قاعدة بيانات `notify_admins(event, title, message, submission_id, target_type, target_id)` تتحقق أن المستدعي عميل مسجّل، وأن الطلب/العنصر يخصه، وتأخذ customer_id واسم العميل من القاعدة لا من المتصفح. المسؤول يستطيع الإنشاء أيضًا.

**الصلاحيات (RLS + GRANT):**
- العميل: يقرأ/يعدّل حالة القراءة والأرشفة لإشعاراته فقط (القائم أصلًا + تقييد التعديل على الحقول is_read/archived_at عبر trigger). لا يرى `admin_notifications` إطلاقًا.
- المسؤول: يقرأ `admin_notifications`؛ في `admin_notification_states` يقرأ ويكتب سجلاته هو فقط (admin_user_id = حسابه).
- لا حذف نهائي من الواجهة لأي طرف.

**Realtime:** إضافة `notifications` و`admin_notifications` و`admin_notification_states` إلى النشر المباشر (الحماية تبقى عبر RLS).

## 2. طبقة الإشعارات في الكود

ملف موحّد جديد `src/lib/notifications.ts`:
- `notifyCustomer(...)` و`notifyAdmins(...)` بأعمدة صريحة (event, target_type, target_id, submission_id).
- جلب/قراءة/قراءة الكل/أرشفة للعميل وللمسؤول الحالي.
- `resolveTarget(n)` يحدد الوجهة من target_type/target_id فقط — إلغاء البحث عن «عقد/سند/مستند» في العنوان.
- إلغاء الاعتماد على `rifans_offline_notifications` ومسح المفتاح القديم من المتصفح مرة واحدة (لا مساس ببيانات القاعدة).

## 3. الأحداث (النصوص كما وردت في الأمر)

| الحدث | إلى | الوجهة |
|---|---|---|
| تقديم طلب جديد | العميل «تم استلام طلبك» + جميع المسؤولين «طلب جديد» | الطلب |
| قيد المراجعة / موافقة / رفض (بتعليق المسؤول) / اكتمال | العميل | الطلب |
| طلب مستندات إضافية | العميل | الطلب المحدد نفسه |
| إرسال العميل للمستندات/البيانات (الطلب المفتوح) | جميع المسؤولين «تم استلام مستندات من العميل» | الطلب المرتبط |
| إصدار عقد | العميل | العقد |
| توقيع العقد | جميع المسؤولين «تم توقيع العقد» (والبريد يبقى) | الطلب/العقد |
| إصدار فاتورة أو بديلة | العميل «فاتورة جديدة ... رقم {الطلب}» | الفاتورة |
| إصدار سند أو بديل | العميل «سند لأمر بانتظار التوقيع» | السند |
| توقيع السند | جميع المسؤولين «تم توقيع السند لأمر» | الطلب/السند |
| عميل جديد أكمل بياناته | جميع المسؤولين «عميل جديد» (والبريد يبقى) | ملف العميل |
| تحديد/إلغاء موعد، طلب مفتوح جديد، طلب سداد | العميل (بنفس النصوص الحالية) | الطلب / الطلب المفتوح / المدفوعات |

- تسجيل المبلغ الفعلي: بلا إشعار.
- **تسجيل سداد الفاتورة:** لا يوجد حاليًا إجراء إداري يحوّل الفاتورة إلى «مدفوعة» (تاريخ السداد يُعرض فقط). لذلك لن يُضاف هذا الإشعار ولن تُنشأ وظيفة سداد جديدة، ويُذكر في التقرير كبند يحتاج قرارك.

## 4. الواجهة (بدون إعادة تصميم)

**العميل (الجرس العلوي + لوحة العميل):** مصدر واحد مشترك، تحديث مباشر، الأحدث أولًا، العداد لغير المقروء لديه فقط مع 99+، الضغط = مقروء ثم الوجهة، «تحديد الكل كمقروء» في القائمة المنسدلة واللوحة، أرشفة إشعار واحد. إلغاء التحديث كل دقيقتين كآلية أساسية.

**المسؤول («سجل التنبيهات والنشاط» والجرس والعدادات):** يعرض الإشعارات الإدارية فقط، مع اسم العميل، العنوان، الوصف، التاريخ والوقت، مقروء/غير مقروء، أيقونة حسب النوع. الضغط = مقروء للمسؤول الحالي ثم فتح الطلب/العميل في اللوحة. البحث يعمل (العنوان، الوصف، اسم العميل، رقم الطلب). «تحديد الكل كمقروء» للمسؤول الحالي. زر السلة يصبح أرشفة لي فقط. العدادات تحسب غير المقروء للمسؤول الحالي فقط.

## 5. الاختبار ثم التنظيف
- عميلان تجريبيان ومسؤولان تجريبيان (بيانات اختبار فقط، تُحذف بعد الاختبار).
- الدورة: طلب → مستندات → رفع → عقد → توقيع → فاتورة → سند → توقيع → اكتمال، والتحقق من الوصول الفوري دون تحديث الصفحة.
- مسؤولان: نفس الإشعار لكليهما، قراءة وأرشفة الأول لا تؤثر على الثاني، العدادات مستقلة.
- العميل الثاني لا يرى إشعارات الأول، والعميل لا يرى الإشعارات الإدارية، ولا تكرار من التخزين القديم، والبحث والروابط وتحديد الكل.
- حذف بيانات الاختبار فقط، ثم تقرير التنفيذ بالبنود العشرين المطلوبة.
