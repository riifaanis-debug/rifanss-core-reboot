# تقرير فحص نظام الإشعارات الحالي (قراءة فقط — لم يُعدَّل أي شيء)

## 1. الواجهة

**العميل**
- أيقونة جرس في الشريط العلوي للموقع (Header) وجرس داخل لوحة العميل (CustomerDashboard).
- الضغط يفتح قائمة منسدلة بعنوان «التنبيهات»: آخر 20 إشعارًا (في اللوحة آخر 30). كل عنصر: نقطة (ذهبية = غير مقروء)، العنوان، الوصف (سطران)، الوقت النسبي («منذ...»). عند عدم الوجود: «لا توجد تنبيهات».
- العدّاد: رقم أحمر على الجرس = عدد الإشعارات غير المقروءة (is_read = false)، ويظهر «99+» فوق 99.
- «تحديد الكل كمقروء»: موجود في لوحة العميل فقط، وغير موجود في قائمة الشريط العلوي.
- الحذف: لا يوجد حذف لإشعار واحد ولا للكل (سياسات القاعدة تمنع العميل من الحذف أصلًا).
- الضغط على إشعار: يُعلَّم مقروءًا ثم ينتقل حسب النوع أو كلمة في العنوان:
  - عقد ← `#/contract/{submission_id}`
  - سند ← `#/promissory/{submission_id}`
  - فاتورة ← `#/invoice/{submission_id}`
  - طلب مفتوح / system / «مستند» ← تبويب الطلبات المفتوحة
  - غير ذلك ← يبقى في اللوحة أو تبويب الطلبات.

**المسؤول**
- جرس في الشريط العلوي للجوال، وزر «الإشعارات» في القائمة الجانبية ومربع إحصائية، وقسم «آخر التنبيهات» في الرئيسية (4–5 عناصر).
- الضغط يفتح تبويب «سجل التنبيهات والنشاط»: اسم العميل + العنوان + التاريخ والوقت الكامل + الوصف، وأيقونة حسب النوع.
- الضغط على الإشعار نفسه لا ينقل إلى أي مكان ولا يعلّمه مقروءًا.
- حقل «بحث في التنبيهات» موجود لكنه لا يعمل (غير مربوط).
- زر سلة الحذف يظهر لكنه لا ينفّذ شيئًا.
- لا يوجد «تحديد الكل كمقروء» للمسؤول. العدّاد يحسب كل الإشعارات غير المقروءة لكل العملاء.

**الترتيب والتحديث**
- الأحدث أولًا (ترتيب created_at تنازليًا) في الطرفين.
- العميل: الشريط العلوي يحدّث كل دقيقتين وعند فتح القائمة. لوحة العميل فيها اشتراك تحديث مباشر، لكن جدول الإشعارات غير مفعّل للتحديث المباشر في القاعدة (المفعّل: الرسائل والفواتير فقط)، فلا تظهر الإشعارات الجديدة فورًا.
- المسؤول: تُحمَّل مرة عند فتح اللوحة، ولا تحديث تلقائي حتى إعادة التحميل.
- الإشعارات القديمة: لا حذف ولا أرشفة ولا انتهاء صلاحية؛ تبقى للأبد. توجد أيضًا نسخة محلية في ذاكرة المتصفح (`rifans_offline_notifications`) تُدمج مع القائمة.

## 2. قاعدة البيانات

جدول واحد: `notifications` (حاليًا 0 سجلات).

| العمود | الوظيفة |
|---|---|
| id (text) | معرّف نصي يُولَّد في المتصفح مثل NOT-{وقت} |
| user_id (text) | العميل صاحب الإشعار ← app_users.id |
| submission_id (text) | رقم الطلب المرتبط (اختياري) |
| title / message | العنوان والوصف |
| type | نوع الإشعار (نص حر، افتراضي system) |
| is_read | مقروء/غير مقروء (افتراضي false) |
| created_at | التاريخ والوقت |

- لا يوجد عمود يميّز إشعار العميل عن المسؤول، ولا عمود مستلم مسؤول. لا يوجد مرجع مباشر لرقم العقد أو السند أو الفاتورة؛ الربط فقط عبر submission_id.
- الصلاحيات: العميل يقرأ ويحدّث إشعاراته فقط؛ المسؤول يقرأ الكل ويحذف. الإنشاء: لنفسه أو للمسؤول أو بواسطة المسؤول. العميل لا يرى إشعارات عميل آخر.

## 4. القنوات الخارجية
- البريد عبر Resend: يُستخدم فقط لتنبيه المسؤول (notify-admin) عند طلب جديد، وتوقيع العقد، وعميل جديد، وبعض النماذج. يحتاج إعداد بريد المسؤول، وإن غاب يُتخطى بصمت. لا يُرسل بريد للعميل عن الإشعارات (البريد للعميل يستخدم رمز التحقق فقط).
- SMS / WhatsApp / Push: غير مرتبطة (زر WhatsApp العائم رابط تواصل فقط).
- المستلم الإداري: لا يوجد مسؤول محدد؛ كل المسؤولين يرون كل الإشعارات في الجدول، والبريد يذهب إلى عنوان إداري واحد.

- الجداول: notifications (وقراءة app_users للأسماء).

## 6. مشاكل ونقاط ناقصة (بدون إصلاح)
1. لا يوجد إشعار داخل الموقع للمسؤول عند طلب جديد أو توقيع عقد أو توقيع سند أو عميل جديد؛ فقط بريد مشروط.
2. تبويب إشعارات المسؤول يعرض كل إشعارات العملاء (الموجهة لهم) كأنها نشاط، ولا فصل بين إشعار العميل والمسؤول.
3. الإشعار الوحيد «للمسؤول» (إرسال طلب مفتوح) يُحفظ باسم العميل فيظهر أيضًا في جرس العميل، ويعتمد على معرّف من ذاكرة المتصفح قد يفشل.
4. عند المسؤول: الضغط لا ينقل ولا يعلّم مقروءًا، البحث لا يعمل، زر الحذف لا يعمل، لا «تحديد الكل كمقروء»، والعدّاد يعدّ غير المقروء لكل العملاء.
5. التحديث المباشر لا يعمل للإشعارات (غير مفعّل في القاعدة)؛ العميل ينتظر حتى دقيقتين، والمسؤول يحتاج إعادة التحميل.
6. التوجيه يعتمد على كلمات في العنوان («عقد»، «سند»، «مستند»)، فإشعار «طلب مستندات» يفتح الطلبات المفتوحة لا الطلب نفسه.
7. لا إشعار عند تسجيل نتيجة الطلب، أو تغيير حالة الفاتورة والسداد، أو توقيع السند.
8. نسخة محلية مكررة من الإشعارات في ذاكرة المتصفح قد تُظهر إشعارات لا توجد في القاعدة أو بحالة قراءة مختلفة.
9. معرّفات الإشعارات مبنية على الوقت في المتصفح، ويمكن أن تتكرر إذا أُنشئ إشعاران في نفس اللحظة.
10. لا توجد مراجع مباشرة للعقد أو السند أو الفاتورة، ولا سياسة للإشعارات القديمة.
11. «تحديد الكل كمقروء» غير موجود في قائمة الشريط العلوي للعميل.

لن يُنفَّذ أي تعديل؛ بانتظار تعليماتك بعد مراجعة التقرير.
