# نقل موقع Rifanss من GitHub واعتماده كنسخة نهائية

استبدال الموقع الحالي (صفحة فارغة من القالب) بمشروع المستودع بالكامل: 61 مكوّن رئيسي + 49 مكوّن واجهة، جميع الصفحات والنماذج والعقود والفواتير ولوحات الإدارة والعملاء، الصور والأصول، وقاعدة البيانات والوظائف الخلفية.

لن يتم تغيير التصميم أو النصوص أو الواجهات. التعديلات التقنية فقط بالقدر اللازم للتشغيل داخل Lovable.

## ما سيتم نقله كما هو

- جميع الصفحات والمسارات الداخلية للموقع (التنقل في المستودع يعمل عبر الروابط الداخلية بنفس طريقته الحالية، فلن يتغير سلوك التنقل).
- كل المكونات: الرئيسية، المجالات، الخدمات الإلكترونية، التنازل، الحاسبة، العقود، السندات، الفواتير، بطاقة العميل، الدفع، الدردشة، لوحة الإدارة، لوحة العميل، الأسئلة الشائعة، التذييل، واتساب العائم… إلخ.
- الملفات والبيانات المساعدة: كتالوج الأقسام، مجالات الأعمال، قوالب العقود، قوالب واتساب، سياسات الخصم، مناطق المملكة، المحفظة.
- الصور والشعارات والخطوط العربية (Tajawal / Cairo) وملف التنسيقات `index.css` كامل (664 سطراً) دون تعديل قيم التصميم.

## قاعدة البيانات والحسابات

- تشغيل Lovable Cloud كقاعدة بيانات المشروع.
- تطبيق جميع ملفات قاعدة البيانات الموجودة في المستودع (18 ملفاً) بنفس الجداول والصلاحيات وسياسات الحماية والأدوار.
- تحويل تسجيل الدخول والتسجيل والتحقق برمز OTP والأدوار (مدير/عميل) للعمل على Lovable Cloud.
- البيانات والمستخدمون الحاليون في القاعدة القديمة لا تُنقل تلقائياً: بعد ظهور الموقع سأطلب منك ملفات تصدير (CSV/JSON) للجداول والمستخدمين من لوحة Supabase الحالية، وسأستوردها مع الحفاظ على الأرقام التعريفية والربط. عند أول دخول للمستخدم القديم يؤكد بريده ويعيّن كلمة مرور جديدة.

## الخدمات الخارجية

الوظائف الخلفية الثمانية المستخدمة في الموقع (إشعار الإدارة، إرسال ورقة التحقق OTP، التحقق من الدخول، طلب الإعفاء، طلب PayPal، مزامنة HubSpot، التحقق من النطاق) ستُنقل بنفس منطقها وتُشغّل على خادم Lovable.

بعد اكتمال النقل سأطلب منك المفاتيح التالية عبر النموذج الآمن (لا تُكتب في المحادثة ولا في الكود): بريد وكلمة مرور الإدارة، مفتاح Resend للبريد، مفاتيح PayPal، مفاتيح واتساب (التوكن ورقم المرسل والقالب)، مفتاح HubSpot.

## تفاصيل تقنية

- **الحذف الكامل**: إزالة صفحة القالب الحالية ومكوناتها؛ لا يبقى إلا ما يلزم لتشغيل بيئة Lovable (طبقة الجذر، إعداد Vite، ملف التنسيق الجذري).
- **الإطار**: المشروع الأصلي Vite SPA بتوجيه عبر `window.location.hash`؛ منصة Lovable مثبتة على TanStack Start. الحل: تركيب `src/App.tsx` كما هو داخل مسار شامل واحد في `src/routes` يعمل على العميل فقط (`ssr: false` + `ClientOnly`)، مع الحفاظ على `AuthProvider` و`LanguageProvider` و`scrollManager` بدون تغيير منطق التوجيه.
- **التنسيقات**: المستودع يستخدم Tailwind 3 مع `tailwind.config.ts`؛ البيئة هنا Tailwind 4. سيُنقل `index.css` كما هو وتُترجم إعدادات `tailwind.config.ts` (الألوان brand/gold/page، الخطوط، الحركات، الحاويات، إضافة typography) إلى `@theme` و`@utility` في `src/styles.css` بنفس القيم حرفياً. تحميل الخطوط عبر `<link>` في ملف الجذر.
- **الحزم**: تثبيت جميع الاعتماديات (Radix، recharts، jspdf، html2canvas، xlsx، qrcode، motion، embla، date-fns، zod، react-hook-form، sonner، supabase-js، bcryptjs…). أي حزمة غير متوافقة مع خادم Lovable ستُستدعى داخل كود العميل فقط.
- **Supabase client**: استبدال المفتاح والرابط الثابتين في `src/integrations/supabase/client.ts` بمتغيرات بيئة Lovable Cloud؛ لا مفاتيح سرية في الكود.
- **الوظائف الخلفية**: تحويل `supabase/functions/*` إلى `createServerFn` (والمسارات العامة لاستدعاءات PayPal/الويب هوك)، مع إبقاء المدخلات والمخرجات مطابقة حتى لا يتغير أي مكون في الواجهة. المفاتيح تُقرأ من متغيرات البيئة داخل الخادم فقط.
- **التحقق**: بناء نظيف + فحص الأنواع، ثم فتح الصفحة الرئيسية وعدداً من الصفحات (الخدمات، المجالات، التنازل، العقد، لوحة الدخول) في متصفح آلي لالتقاط أي خطأ في الشاشة أو السجل، وتجربة تسجيل دخول واحد كامل بعد تشغيل القاعدة.

## الترتيب

1. تشغيل Lovable Cloud وتطبيق ملفات قاعدة البيانات.
2. حذف صفحة القالب ونقل كل ملفات المستودع (`src` والأصول والإعدادات) وتثبيت الحزم.
3. تركيب التطبيق داخل مسار Lovable وترجمة إعدادات Tailwind.
4. نقل الوظائف الخلفية وربط المتغيرات.
5. البناء والتحقق وإصلاح أي أخطاء.
6. طلب المفاتيح عبر النموذج الآمن، ثم طلب ملفات تصدير البيانات والمستخدمين.

## نقاط تحتاج انتباهك

- لن يعمل الدفع وإرسال البريد والواتساب وHubSpot حتى تُدخل مفاتيحها.
- المحتوى القديم (الطلبات، العملاء، العقود) سيظهر فقط بعد استيراد ملفات التصدير.
