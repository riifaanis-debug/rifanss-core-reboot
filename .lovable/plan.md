# ربط الموقع بـ Snap Pixel

## نتيجة الفحص
- لا يوجد أي كود Snap Pixel مثبت حاليًا (روابط سناب شات في القائمة والفوتر فقط) — لا خطر تكرار.
- لا يوجد شريط موافقة حالي.
- حفظ الطلبات يمر عبر دالة واحدة (`submitRequest`) تُستخدم في نماذج الإعفاء والخدمات والمنتجات. ملاحظة: عند فشل الحفظ تحفظ الطلب محليًا بصمت — لن يُحسب هذا نجاحًا.
- إنشاء الحساب يكتمل فقط بعد التحقق من رمز OTP في صفحة الدخول.

## ما سيُضاف
1. **شريط موافقة صغير** لكل الزوار أسفل الشاشة (قبول / رفض بنفس السهولة)، بألوان وخطوط الموقع الحالية، مع رابط «إعدادات الإعلانات» في الفوتر لتغيير الاختيار لاحقًا. لا يُحمَّل Pixel إطلاقًا قبل القبول، ويتوقف فورًا عند الرفض/السحب (وفي التبويبات الأخرى).
2. **Snap Pixel الرسمي** بالمعرّف `2196cf76-372a-41d9-b85a-ba6a4e6d1f45`، يُحمَّل مرة واحدة فقط.
3. **الأحداث** (بدون أي بيانات شخصية، بدون بريد أو جوال):
   - PAGE_VIEW: عند كل تغيير صفحة، مرة واحدة لكل عنوان، والعنوان المرسل بدون أي معرّفات (أرقام طلبات/عقود/فواتير تُحذف).
   - VIEW_CONTENT: عند فتح صفحات الخدمات التمويلية (صفحات الخدمة/الفئة/المنتج/المجال)، باسم فئة عام فقط.
   - START_CHECKOUT: عند فتح نموذج طلب جديد (مرة واحدة لكل فتح).
   - SIGN_UP: بعد نجاح التحقق من OTP وإنشاء الحساب فعليًا فقط.
   - CUSTOM_EVENT_1 (اسم الحدث FinanceApplicationSubmitted): بعد نجاح حفظ الطلب في قاعدة البيانات فعليًا فقط، وليس عند الحفظ المحلي الاحتياطي.
4. **سياسة الخصوصية وسياسة ملفات الارتباط**: إضافة فقرة توضح استخدام Snap Pixel، البيانات المرسلة، الغرض (قياس الإعلانات)، وكيفية السحب.
5. سجل موافقة محلي: الاختيار، وقته، ورقم نسخة نص الإشعار.

## ما لن يُلمس
التصميم الحالي، الصور، الفيديو، وظائف البوابة، قاعدة البيانات، تسجيل الدخول، الصلاحيات.

## الاختبار
- Playwright: قبل الموافقة لا طلبات إلى Snapchat؛ بعد القبول يُحمَّل Pixel مرة واحدة؛ PAGE_VIEW واحد لكل تنقل؛ عند الرفض لا شيء؛ التحقق من خلو المُرسل من بيانات شخصية.
- بعد النشر: التحقق عبر Snap Pixel Helper / Events Manager (خطوة متبقية عليك).

## تفاصيل تقنية
- `src/lib/snapPixel.ts`: تحميل السكربت ديناميكيًا بعد الموافقة، `snaptr('init', id)` بدون user_email/phone، دالة `track()` تقرأ الموافقة لحظة الإرسال، وdedupe لـ PAGE_VIEW حسب آخر عنوان.
- `ConsentBanner.tsx` يُركّب في `App.tsx`؛ مزامنة التبويبات عبر حدث `storage`.
- تعديل `submitRequest` ليُعيد علامة نجاح الحفظ الفعلي دون تغيير سلوكه، واستدعاء الحدث من النماذج الثلاثة.
- SIGN_UP من فرع `register` في `AuthPage` بعد نجاح verify-otp.
